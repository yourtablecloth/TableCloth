# Safe Mode 사용과 Windows Sandbox 중지 오류 진단

2026년 10월 9일 기준 `develop` 브랜치에 Safe Mode를 추가했습니다. 사용자가 이 기능을 켜면 식탁보는 호스트 폴더를 공유하지 않는 Windows Sandbox를 준비합니다. 배포 버전에서 사용하려면 이번 변경을 포함한 빌드가 필요합니다.

이 문서는 실행 정책, 사용할 수 없는 기능, 게스트 다운로드와 로그, 중지 오류 비교 절차, 버그 제보 항목을 설명합니다.

먼저 실행 정책과 기능 제한을 살펴보겠습니다. 이후 비교 절차를 통해 호스트의 중지 오류와 게스트의 준비 실패를 구분합니다. 기능 범위는 [이슈 #311](https://github.com/yourtablecloth/TableCloth/issues/311)을 따릅니다.

> 2026년 10월 9일에 개발 브랜치의 구현을 확인했습니다. 환경 설정에서 Safe Mode를 켜서 사용할 수 있습니다. 프리뷰 동작은 정식 출시 전에 달라질 수 있습니다.

## 호스트 공유를 제외한 실행 정책

환경 설정의 **샌드박스 세션 > Safe Mode 사용**을 선택합니다. 빠른 시작 화면은 **실행 모드: Safe Mode**를 표시합니다. 실행 전 안내에서 기능 제한을 확인하고 시작 여부를 선택할 수 있습니다. 빠른 시작, 카탈로그, 설치형 딥링크, AI의 카탈로그 실행과 기존 명령줄 실행은 공통 빌더의 정책을 따릅니다. 브라우저 전용 실행은 공유 없는 Edge 실행을 유지합니다.

| 설정 | Safe Mode 정책 | 영향 |
| --- | --- | --- |
| 호스트 폴더 | `MappedFolders` 요소 생략 | App, Data, NPKI, 사용자 폴더와 호스트 .NET 런타임 매핑 제외 |
| 클립보드와 장치 | 클립보드, 프린터, 카메라와 마이크를 명시적으로 Disable | 호스트와 게스트 사이의 복사 및 붙여넣기와 장치 공유 제한 |
| GPU | 명시적으로 Disable | 소프트웨어 렌더링 사용 |
| 네트워크 | 명시적으로 Enable | 다운로드와 웹 사이트 이용 유지 |

일반 모드의 설정은 보존합니다. Safe Mode를 끄면 저장한 설정을 다시 사용합니다. Windows Sandbox 자체의 가상화와 호스트 서비스 사용은 계속합니다. 각 항목의 동작은 [Windows Sandbox 설정 명세](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file)에서 확인할 수 있습니다.

## 게스트 다운로드와 기능 제한

게스트 준비 흐름을 정리하겠습니다. 생성한 WSB는 게스트 안에서 Express와 같은 준비 스크립트를 다운로드합니다. 게스트는 공식 최신 안정 릴리스에서 x64 또는 ARM64용 SporkBootstrap을 받습니다. 부트스트랩은 Spork를 다운로드하고 압축을 풀어 실행합니다. 따라서 프리뷰 호스트와 안정 버전 게스트 사이에 버전 및 기능 차이가 생길 수 있습니다. 호스트 실행 파일과 카탈로그 캐시는 게스트에 전달하지 않습니다. [Express 설계 문서](EXPRESS_BOOTSTRAPPER_DESIGN.md)

호스트의 공동인증서와 ZScaler 루트 인증서를 사용할 수 없습니다. 해당 루트를 요구하는 관리형 네트워크는 HTTPS 다운로드를 차단할 수 있습니다. 식탁보는 이 실패를 우회하려고 인증서 검증을 해제하지 않습니다. 모바일 인증처럼 호스트 파일을 요구하지 않는 인증 수단을 지원하는 사이트에서 사용할 수 있습니다. 게스트의 파일, 즐겨찾기와 사용 기록은 Sandbox 종료 시 삭제합니다.

호스트의 유휴 자동 종료 등 실행 옵션은 전달하지 않습니다. 초기 준비 단계는 공용 DNS 폴백 설정을 따릅니다. 다운로드한 안정 버전 게스트는 자체 기본값을 사용합니다. 폴백을 끄면 초기 준비 단계에서 DNS 설정을 바꾸지 않습니다.

## 실행 로그와 준비 실패의 구분

실행 기록에서는 각 단계의 로그를 짚어보겠습니다. 게스트 바탕 화면의 `tablecloth-safe-mode.log`는 실행 모드, 아키텍처, 런처 다운로드 주소와 실제 Spork 실행 파일 버전을 기록합니다. `spork-bootstrap.log`는 패키지 다운로드 주소와 부트스트랩 결과를 기록합니다. 호스트의 식탁보 로그는 모드와 게스트 준비 경로를 기록합니다. WSB 생성 성공만으로 다운로드와 게스트 실행 성공까지 확정하지 않습니다. [부트스트랩 소스](../src/Spork.Bootstrapper/Program.cs)

다운로드나 준비에 실패하면 준비 콘솔이 오류를 표시하고 사용자의 입력을 기다립니다. 부트스트랩의 재시도 및 닫기 버튼도 유지합니다. 공유 Data와 클립보드 내보내기를 제공하지 않으므로 Sandbox를 닫기 전에 허용된 보고 경로로 게스트 로그를 기록할 수 있습니다. 게스트의 다운로드 오류와 호스트 PC의 블루스크린을 구분하여 제보합니다.

## 비교 조건을 유지하는 중지 오류 진단

[이슈 #313](https://github.com/yourtablecloth/TableCloth/issues/313)의 진단 기록은 네 덤프가 VSMB 파일 열기 경로의 `nrpmonka.sys + 0x58E1` NULL 읽기를 가리킨다고 설명합니다. 제보자는 Sandbox 단독 실행, 누리랩 드라이버 종료 후 설치형 실행과 무설치 실행에서 오류가 발생하지 않았다고 회신했습니다. 정확한 종료 조작과 무설치 비교 당시 누리랩 활성화 상태, 특정 공유 폴더의 관여는 확인되지 않았습니다. 다른 PC에서 과거에 오류를 경험하지 않았다는 회신만으로 동일 조건 비교를 확정하지 않습니다.

보안 제품이 공식적으로 보호 일시 중지를 지원하면 해당 설정과 비교 결과를 기록하고 테스트 후 보호를 다시 활성화합니다. 제품 UI의 보호 중지가 커널 드라이버 언로드까지 보장하지는 않습니다. 진단 과정에서 드라이버를 강제로 종료하거나 언로드 또는 제거하는 방법을 안내하지 않습니다. Microsoft는 [미니필터 로드와 언로드의 별도 수명 주기](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/loading-and-unloading)를 설명합니다.

다만 Safe Mode에서도 호스트 중지 오류가 발생할 수 있습니다. 그 결과만으로 네트워크를 원인으로 확정하지 않습니다. 네트워크를 끈 진단용 WSB는 Spork를 다운로드하지 못합니다. 다운로드 단계에 도달하지 못한 결과를 식탁보 정상 실행으로 기록하지 않습니다. 식탁보는 네트워크를 끈 실행 모드를 제공하지 않습니다. 네트워크가 실제 촉발 조건으로 확인되면 호환성 문제를 해결하기 전까지 해당 PC의 현재 Windows 및 보안 솔루션 환경에서는 식탁보를 사용할 수 없습니다. 공급업체 또는 Windows 지원 경로에서 호환성을 조사할 수 있습니다.

## 비교 기록과 버그 제보 항목

제보 항목을 검토하겠습니다. [버그 제보 템플릿](../.github/ISSUE_TEMPLATE/------.md)에 비교 조건과 실패 단계를 기록하면 진단 범위를 좁힐 수 있습니다.

1. 정확한 Windows 빌드, CPU 아키텍처, 식탁보 호스트 및 게스트 버전, 보안 제품과 드라이버 버전을 기록합니다.
2. Windows Sandbox 단독 실행, 일반 식탁보, 공식 무설치 WSB와 Safe Mode 결과를 각각 기록합니다.
3. 무설치와 Safe Mode를 포함한 각 비교의 보안 제품 보호 상태를 기록합니다.
4. 게스트 시작 전, 다운로드 중, Spork 준비 중 또는 사이트 이용 중 어느 단계에서 실패했는지 기록합니다.
5. 호스트 중지 오류의 중지 코드와 시각, 새 미니덤프를 보존합니다. 덤프에는 민감정보가 들어갈 수 있으므로 합의한 비공개 경로로 전달합니다.
6. 다운로드 실패의 게스트 로그와 다른 PC에서 실제 동일 조건으로 비교한 결과를 기록합니다.

여기까지 정리하면 Safe Mode는 온라인 사이트 이용을 유지하면서 선택적인 호스트 공유 경로를 제외합니다. 보안 드라이버의 호환성 조사와 수정은 장기 사안으로 남으며 Safe Mode 비교는 현재 실행 경로의 차이를 확인할 수 있게 합니다.

기록한 보호 상태에서 게스트가 정상 실행하면 기능 제한을 수용할 수 있는 범위에서 임시 실행 경로로 사용할 수 있습니다. 호스트 중지 오류가 계속되면 비교 근거를 보존하고 Windows와 보안 제품의 호환성을 조사한 뒤 사용 재개 여부를 판단할 수 있습니다.
