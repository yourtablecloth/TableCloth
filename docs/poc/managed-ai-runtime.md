# TableCloth AI Preview implementation and verification

Implementation status on September 25, 2026: the `poc/managed-ai-runtime` branch starts at `main` commit `ad43cdaca174b3bd2a6c1ce42c37c97506e8d189`. The installed Codex `0.156.1` profile is authenticated, and a live request through the corrected chat provider succeeded. All 365 offline tests pass. Chat controls and native Markdown rendering have been reviewed using headless screenshots in light and dark themes. Model and skill discovery succeed against the installed runtime without inference. Links offer a choice between the current Windows browser and the existing Sandbox/Spork flow. Actual skill-guided inference, guest installation, guest navigation and host-browser launch remain unverified.

The product-facing name is **TableCloth AI (Preview)**. The `poc/managed-ai-runtime` branch, `docs/poc` directory and `TableCloth.ManagedAi.Poc` diagnostic project retain their original names for traceability. The [original Korean design](managed-ai-runtime-design.ko.md) is preserved as supplied. Its historical statements are a design baseline, not current execution evidence. This report covers the implementation, local checks, consent flow and remaining gates.

## Implementation boundaries

The existing `TableCloth.slnx` includes the five managed-AI projects and a separate `TableCloth.Cli` project. `ManagedAi.Core` owns search/chat contracts, bounded conversation history, link parsing and URL validation. `ManagedAi.OpenAi` owns distribution, authentication, invocation and parsing. `ManagedAi.Windows` owns ACLs, bounded process streams and Windows Job Objects. `ManagedAi.Poc` supplies a diagnostic console host. `ManagedAi.Test` uses the repository's existing MSTest SDK instead of introducing xUnit. `TableCloth.Cli` builds `TableClothCli.exe` for host-side certificate and cached Catalog queries.

The libraries use .NET 10. Windows components retain the existing application's `net10.0-windows10.0.18362.0` target; actual testing used Windows 11 x64 build 26200 and .NET SDK 10.0.401. ARM64 asset selection is tested using fixtures. No ARM64 executable was run.

No catalog database or provider search index is added. See [the shared contracts](../../src/TableCloth.ManagedAi.Core/Contracts.cs) and [the solution](../../TableCloth.slnx).

## Runtime installation and profile isolation

The installer resolves the [official release channel](https://releases.openai.com/codex/channels/latest), restricts requests and redirects to the official HTTPS host, verifies the checksum-list digest and both package digests, then extracts a bounded TAR into staging. It rejects traversal, Windows device names, alternate streams, duplicate names and links. Layout and `codex-cli <version>` checks precede activation. `File.Replace` maintains the previous state, and a failed post-activation check restores both state files. Updates, authentication and searches share an exclusive operation lock.

Only `%LOCALAPPDATA%\TableCloth\ManagedAi` contains managed runtime data. The app never runs the official installer or changes the host PATH, registry, global Codex installation or global Codex profile. Profile configuration uses ChatGPT-only file authentication and limits its ACL to the current user, SYSTEM and Administrators. The application never reads `auth.json`. Unexpected changes to its owned `config.toml` stop execution.

The official metadata client selected version `0.156.1`, target `x86_64-pc-windows-msvc`, with package SHA-256 `a2e017db9807e6a2269a26fea0e1d9546469cef4d472a33016bc9f3ad7d3b733`. The user subsequently installed the runtime. Its managed state and actual executable version match this release, and the live provider used that installation. The package archive was not independently rehashed during the repair. Installation behavior follows [the implementation](../../src/TableCloth.ManagedAi.OpenAi/Distribution/OpenAiCodexPackageInstaller.cs).

## Managed skills and exclusive discovery

The built-in [certificate-expiry skill](../../src/TableCloth.ManagedAi.OpenAi/Skills/Bundled/tablecloth-certificate-expiry/SKILL.md) is seeded into the dedicated profile on the first skill synchronization. A marker preserves deliberate removal across later refreshes and runtime reinstallations. When the skill is enabled and a user asks about certificate expiry, the chat UI asks before invoking the fixed host-side `TableClothCli.exe certificates expiring --within-days 30 --with-catalog-summary` command and sending its minimal JSON result to OpenAI. Codex retains no shell access. The scanner reads bounded `signCert.der` public certificate files, checks for `signPri.key` without reading it, and omits names and paths by default. The local-only `--details` option exposes those fields to the CLI user. The result contains scan time, expired and expiring entries, partial-scan counts, and the cached Catalog service count. The Catalog schema cannot associate a particular certificate with a service. A separate `catalog services` CLI command lists cached service URLs and installation-item counts. The TableCloth publish target bundles the Native AOT CLI sidecar.

The bundled [Windows Sandbox skill](../../src/TableCloth.ManagedAi.OpenAi/Skills/Bundled/tablecloth-windows-sandbox/SKILL.md) uses a host bridge to invoke the installed `wsb.exe` alias with fixed arguments. The bridge supports `list`, default `start`, `stop`, `connect`, and `ip`; it resolves an omitted ID only when exactly one running session is reported. The chat asks before `stop` because closing a sandbox discards its state. `exec`, `share`, and arbitrary configuration are not exposed to Codex. The existing TableCloth website-launch path still opens its generated `.wsb` configuration directly. On the development host, `wsb --version` returned `0.8.107.0` and `wsb list --raw` returned an empty `WindowsSandboxEnvironments` array on 2026-09-25. The [Microsoft CLI reference](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-cli) describes the available commands; availability on other hosts depends on the installed Windows Sandbox version.

OpenAI documents a skill as a `SKILL.md` folder with optional references, scripts and assets. Codex first receives its name and description, then loads the full instructions when the request matches. TableCloth stores imported user skills under `%LOCALAPPDATA%\TableCloth\ManagedAi\profiles\openai-codex\codex-home\skills`; per-skill choices live in the sibling `tablecloth-skills.json`. Runtime releases remain under `runtimes\openai-codex`, so installing, updating or deleting that runtime tree does not delete user skills or their enabled state. See the [official skill description](https://developers.openai.com/plugins/concepts/skills) and [Codex skill configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference).

`CODEX_HOME` isolation alone is insufficient on Codex `0.156.1`: a read-only native `skills/list` probe also discovered skills from the Windows user's normal Codex and Agent Skills locations. Before each search or chat turn, `OpenAiCodexSkillManager` starts app-server only long enough to initialize and list skill metadata. It does not start a thread or turn. The manager writes `tablecloth-skills.config.toml` with `enabled = false` for every discovered manifest outside the owned skills directory. The following `exec` command loads that overlay with `--profile tablecloth-skills`. Codex-owned `.system` skills inside the dedicated profile remain available. A read-only `debug prompt-input` probe against the installed runtime confirmed that a managed fixture skill entered the model-visible catalog while an externally located fixture entry disabled by the overlay did not. No inference request was made.

The main Options window has a dedicated **AI 스킬** tab with a catalog, descriptions, paths, enabled state, import, toggle, removal, refresh and folder access. The chat account/settings panel offers the same management actions, and its header shows how many enabled skills are available to the next conversation. This count does not measure which skills a particular model response actually invoked. If the runtime is absent, the app can still list, toggle, import and remove owned folders; descriptions are verified when Codex is installed. Removal requires confirmation and deletes only a direct child of the owned skills directory after checking nested reparse points. Import accepts one root `SKILL.md`, rejects UNC paths and reparse points, limits each file to 25 MiB, limits the bundle to 500 files and 50 MiB, and copies through an owned staging directory. Invalid native metadata stops skill activation with a fixed error. The current profile still disables shell tools, hooks, subagents, remote plugins and automatic MCP dependency installation. This Preview therefore supports instruction-oriented skills; script execution and automatic tool dependency setup remain outside the current boundary. See the [skill manager](../../src/TableCloth.ManagedAi.OpenAi/Skills/OpenAiCodexSkillManager.cs), [settings tab](../../src/TableCloth.App/Dialogs/OptionsWindow.axaml), [native exchange](../../src/TableCloth.ManagedAi.OpenAi/Skills/CodexSkillListExchange.cs) and [skill tests](../../src/TableCloth.ManagedAi.Test/SkillTests.cs).

Login checks the existing managed session before starting OAuth. The primary connection action uses browser login and automatically verifies `Logged in using ChatGPT` before loading models. Device-code login remains available in the OpenAI account/settings panel; its verification link and code are shown only while waiting. Authentication URLs are restricted to known OpenAI authorization paths. Transient login details are cleared after completion or cancellation and never enter application diagnostics. The diagnostic console also displays login instructions. Device login availability depends on account/workspace settings, as described in [the authentication documentation](https://learn.chatgpt.com/docs/auth).

After a report that the browser showed “Signed In Codex” while the app still waited, a read-only check confirmed that the managed ChatGPT session was already authenticated. A synthetic process fixture reproduced a wait until timeout when a child inherited stdout/stderr after its parent exited. The process runner now closes its Job Object on parent exit before awaiting pipe EOF. Authentication also probes `login status` once per second while login is pending; a verified ChatGPT status stops the remaining login process, awaits cleanup, then reports completion. A banner, URL, or successful exit without a saved ChatGPT session cannot complete login. User cancellation still cancels the operation. The window clears login instructions before loading models and ignores late login progress callbacks. These paths have regression coverage in [process tests](../../src/TableCloth.ManagedAi.Test/ProcessTests.cs), [login tests](../../src/TableCloth.ManagedAi.Test/LoginFlowTests.cs) and [window tests](../../src/TableCloth.Test/ManagedAiWindowTests.cs). The exact process state during the reported hang was no longer available, and a fresh OAuth round trip after this fix remains unverified.

## Search execution and privacy

The provider sends the prompt through stdin to an absolute executable path. Child environment filtering excludes inherited API credentials and Codex session settings. The profile disables shell tools, unified execution, hooks, subagents, shell snapshots and remote plugins, and suppresses project instruction loading. Both invocation paths request live search, JSONL, read-only execution and ephemeral sessions using [documented Codex flags](https://learn.chatgpt.com/docs/developer-commands). The installed runtime's `doctor --json` accepted the configuration and reported working authentication and connectivity with no MCP servers. The corrected chat invocation also completed successfully.

Both streams are drained concurrently with byte and line limits. A Windows Job Object kills descendants even if their parent exits; cancellation and the hard timeout also request process-tree termination. Chat requires exit code zero, a successful turn and a bounded final text message. Greetings and clarification may complete without a search; observed web-search events are counted separately. A recoverable reconnect event does not invalidate a subsequent successful turn. Terminal errors and stderr are classified into fixed authentication, subscription, network, configuration or request-format codes.

The structured `search` console command retains its schema and local validation. It additionally requires an observed completed web-search event. The reproduced HTTP 400 failure identified `format: uri` in the response schema as unsupported. Removing that annotation fixes the rejected contract while retaining independent local URL validation. Chat uses plain-text responses without an output schema. Unknown JSON event types are ignored; unsafe structured candidates are removed without opening a browser. See [the provider](../../src/TableCloth.ManagedAi.OpenAi/OpenAiCodexProvider.cs) and [the schema regression test](../../src/TableCloth.ManagedAi.Test/ChatTests.cs).

Application diagnostics accept only fixed outcome codes, version, counts, timestamps and duration. They have seven-day retention, a 5 MiB per-file limit and a 20 MiB aggregate budget. Raw streams, queries, result text, URLs and credentials do not enter these records. Codex's own files and service-side retention remain separate boundaries; their live behavior has not been audited. Authentication follows [the official documentation](https://learn.chatgpt.com/docs/auth).

## Chat controls, Markdown and Catalog-aware links

The Quick Start page and chat window expose **식탁보 AI (Preview)**. The window checks connection status on opening. A single state-dependent action installs the runtime if missing, starts browser login if needed, and loads the model list after authentication. Draft text survives setup. Connected users see a model picker; update, refresh, device-code login, logout and rollback live in the OpenAI account/settings panel. Installation retains its download confirmation. Sending remains disabled until connection and model selection succeed, with a retry action after discovery failure or expired authentication. The composer states that messages go to OpenAI and consume subscription usage.

Shift+Enter sends; Enter inserts a newline. The shortcut uses the tunneling key event before the multiline editor handles it, and duplicate sends are blocked while busy. Every message has a copy action that writes the original Markdown to the clipboard and confirms completion. An assistant placeholder shows an animated themed progress ring, observed search progress and the selected model, while a separate timer shows elapsed seconds. Completion, cancellation and failure remove the placeholder and restore controls. See [the chat window](../../src/TableCloth.App/ManagedAi/ManagedAiWindow.cs).

The **OpenAI 계정 / 설정** button opens a visible in-window panel made from themed buttons. The application's custom theme does not provide `MenuFlyoutPresenter` or `MenuItem` templates, which made the former connection menu invisible. The panel exposes **로그아웃**, **로그아웃 후 다시 로그인**, a signed-out **OpenAI 로그인** action and the managed-skill controls. Reconnection finishes logout before starting browser login; logout failure prevents a new login attempt. Account and runtime actions close the panel. Skill refresh, enablement and removal keep it open so multiple entries can be managed without reopening settings. The chat header shows the number of enabled skills available to the next turn and refreshes when the window regains focus. The close button, Escape and an outside click also dismiss the panel. Keyboard focus stays within its controls, and its scroll area fits the minimum window height. Headless tests use pointer input for account actions and routed button events for a skill row below the initial scroll viewport.

New conversations show five built-in starter prompts: public services, internet banking preparation, tax-service websites, TableCloth usage and certificate expiry. Selection adds the prompt to the composer and preserves an existing draft; it does not send a request, open a website or generate recommendations through the AI provider. The user can edit and explicitly send the message after signing in. Suggestions hide on the first send and return with **새 대화**. An over-limit insertion leaves the draft unchanged. Account-panel and starter screenshots were reviewed in both themes at 640 and 900 pixels; logout/relogin was tested with fixtures without changing the user's actual session. See [the interaction tests](../../src/TableCloth.Test/ManagedAiWindowTests.cs).

Model choices come from the installed Codex's [app-server `model/list` interface](https://learn.chatgpt.com/docs/app-server#list-models-modellist) after initialization, with bounded pagination and hidden/non-text entries excluded. Discovery uses the owned profile, sanitized child environment, operation lock, byte limits, cancellation and a 30-second timeout. It never starts a thread or turn. Each chat request passes the selected identifier explicitly with `--model`, and each completed assistant message keeps that identifier in its header. On this host the read-only check returned seven models with `gpt-6-astra` marked as the provider default. The application's new initial selection was `gpt-6-luna`. This is an observed account/runtime snapshot, not a hard-coded availability list or evidence of successful inference with every model. See [model discovery](../../src/TableCloth.ManagedAi.OpenAi/OpenAiCodexModelCatalog.cs) and [protocol tests](../../src/TableCloth.ManagedAi.Test/ModelCatalogTests.cs).

The picker saves `LastSelectedAiModel` through the existing `IPreferencesManager` and source-generated `PreferenceSettings` JSON. A still-available saved model takes precedence on reopening, refresh and login. Otherwise the selector chooses the lowest verified combined cost for one million uncached input tokens plus one million output tokens. If no usable prices exist, it chooses the newest numeric GPT Luna generation, then the newest dated snapshot within that generation (a moving alias takes precedence). With neither prices nor Luna, it uses the first returned model. Cost ties preserve list order. Unknown models never receive an assumed zero cost. See [selection policy and tests](../../src/TableCloth.ManagedAi.Test/AiModelSelectionTests.cs).

The runtime model catalog does not expose prices. A [bundled rate card](../../src/TableCloth.ManagedAi.OpenAi/OpenAiCodexRateCard.cs), verified on September 25, 2026 against [official OpenAI pricing](https://learn.chatgpt.com/docs/pricing), supplies Standard-speed Codex credits per million text tokens for exact known model IDs. It does not scrape prices at application startup. These reference rates are distinct from API dollars, included subscription limits and actual per-task billing. The application stops comparing the snapshot after 30 days, or if its verification date is in the future; maintaining price-based selection beyond that window requires a newly verified rate card. Available models still come exclusively from the account's runtime response. The hint shows input/output rates and a tooltip with the verification date, cached-input rate, comparison basis and source.

Model changes reload the current preferences before saving, retain unrelated fields and serialize writes from rapid selections. Closing waits for queued writes. Logout and temporary empty model lists do not erase the preference. If a saved model is no longer available, the fallback selection becomes the new saved choice. Save failures leave the current selection usable and show a dedicated notice. Window tests exercise JSON round trips, reopen/login restoration, unavailable saved models, unrelated settings, ordered writes and error recovery; a 640-pixel light-theme screenshot verifies the cost hint.

Follow-up requests include up to 12 prior messages and 20,000 characters, held only in memory. Failed turns do not enter that context. [Markdig 1.4.0](https://github.com/xoofx/markdig) supplies a shared CommonMark/GFM syntax tree for link discovery and rendering. The native Avalonia view supports headings, nested emphasis, strikethrough, ordered/unordered and task lists, blockquotes, horizontal rules, fenced/indented code, inline code, pipe tables, reference links, entities and escapes. Tables and code blocks can scroll horizontally. Code URLs remain literal. HTML is displayed as text and images as their alternative text without fetching remote content. Input size, nesting and node-count limits fall back to bounded plain text rather than crashing the chat window. See [the parser](../../src/TableCloth.ManagedAi.Core/ChatMarkdown.cs) and [the renderer](../../src/TableCloth.App/ManagedAi/ChatMarkdownView.cs).

Plain HTTP/HTTPS URLs, Markdown links, reference links and autolinks in both user and assistant messages are clickable, including older messages and URLs outside the latest response. Each click revalidates the destination, then displays a modal choice with `Windows Sandbox에서 열기`, `현재 브라우저에서 열기` and `취소`. Closing the dialog has the same effect as cancellation. The light and dark application themes render the URL, explanation and all three controls without clipping.

The current-browser choice passes the validated original URL to the Windows shell, which opens the user's default browser. It performs no Catalog lookup, Spork composition or Sandbox launch. The Sandbox choice looks up the link in the application's loaded TableCloth Catalog using the existing `CatalogTargetUrlMatcher`. Matching follows registered-domain and host-label rules; it does not use substring matching or provider-suggested software names. A missing catalog is loaded through the existing cache manager; lookup failures stop the operation instead of silently skipping installation.

An accepted match supplies its service IDs and the original URL to `QuickStartPageViewModel.LaunchForDeepLinkAsync`. This preserves the normal application preferences and Data/NPKI/folder-sharing settings. The existing Sandbox builder starts guest Spork with those IDs and `--target-url`. Spork revalidates the target against the Catalog, composes its package/extension/bootstrap steps and then opens the requested page. Percent-encoded query parameters are preserved. When the existing matcher reports ambiguous candidates, a service-selection dialog chooses one validated candidate; cancellation launches nothing. See [the Catalog adapter](../../src/TableCloth.App/ManagedAi/TableClothBrowserAdapter.cs), [launch bridge](../../src/TableCloth.App/ManagedAi/ManagedAiCatalogLauncher.cs) and [integration tests](../../src/TableCloth.Test/ManagedAiBrowserAdapterTests.cs).

If no Catalog domain matches, the adapter uses the separate `ManagedAiBrowserOnlyUrl` configuration field through `ISandboxLauncher.RunSandboxAsync` and `SandboxBuilder`. The builder validates the URL again and generates a browser-only `.wsb` that opens guest Edge. Only this fallback mode shares no host folders or certificates and disables clipboard, microphone, camera and printer redirection. The URL is encoded as data in the fixed guest startup script. No finance software is installed in this mode. Local/private literal addresses, credential-bearing URLs and non-web schemes remain unlinked. Merely receiving a message never opens a browser or installs software.

The selected URL is necessarily present in the temporary launch files: encoded in `.wsb` for browser-only mode, or escaped in `StartupScript.cmd` for Catalog mode. Existing sandbox cleanup owns those files. They are not application diagnostic records or a chat-history database; normal Spork history/storage behavior applies in Catalog mode. Hostname validation does not establish ownership or reputation and does not prevent public DNS names from resolving to local addresses. See [the generated browser-only specification](../../src/TableCloth.ManagedAi.Windows/BrowserOnlySandboxSpec.cs).

## Live validation and remaining gates

The design requires separate permission for live downloads, authentication and subscription consumption. For this repair, the user authorized at most two provider requests for one fixed public query. The first reproduced the schema rejection; the second used the corrected chat provider and succeeded in 15,872 ms, with nine JSONL events and two completed web-search events. These are two top-level provider requests in total. No additional inference requests were made. The successful request returned a Markdown link to the TableCloth homepage, and its temporary run directory was removed.

Managed-profile login status returned `Logged in using ChatGPT`; the existing OAuth log also showed a successful callback and token exchange. The repair did not sign out the user or repeat OAuth. Device and browser login progress was tested with fixtures, so fresh interactive authentication remains a manual check.
