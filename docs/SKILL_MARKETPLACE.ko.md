# 스킬 마켓플레이스와 원격 카탈로그

2026년 10월 25일 기준으로 이번 구현은 식탁보 `develop` 계열을 대상으로 합니다. 마켓플레이스는 TableClothCatalog의 별도 XML 스킬 카탈로그를 읽고 식탁보 AI 전용 Codex 프로필에 설치한 스킬을 관리합니다. 현재 공개한 Preview 릴리스에는 이번 변경을 포함하지 않습니다.

마켓플레이스에서 후보 검색, 출처와 라이선스 열람, 설치 검토 상태 확인, 로컬 스킬 관리를 함께 제공합니다. 최초 카탈로그에 후보 열두 개를 등록하고 설치 검토 상태를 대기로 유지합니다.

이 문서에서는 창의 사용 경로부터 카탈로그 계약, 설치 허용 조건, 로컬 저장 범위, 검증 범위 순서로 살펴보겠습니다. [English](SKILL_MARKETPLACE.md)

## AI 설정에서 여는 마켓플레이스

마켓플레이스의 진입 경로를 정리하겠습니다. **옵션 > AI 스킬 > 스킬 마켓플레이스 열기**를 선택하면 별도 창을 엽니다. 창에서 카탈로그와 설치된 스킬을 각각 조회할 수 있습니다. 검색으로 목록을 좁히고 카탈로그의 분야 필터로 후보를 선택할 수 있습니다. 후보를 선택하면 출처, 저자, 라이선스, 검토 상태, 적용 조건을 표시합니다.

옵션 탭에는 짧은 사용 안내와 마켓플레이스 열기 버튼만 표시합니다. AI 창의 **OpenAI 계정 / 설정 > 전용 스킬 > 설치된 AI 스킬 관리**를 선택하면 설치된 스킬 탭을 바로 엽니다. 대화 상자를 닫으면 AI 창이 활성 스킬 수와 스킬 사용 상태를 다시 조회합니다.

이어서 카탈로그 조회와 로컬 작업의 관계를 짚어보겠습니다. 두 작업은 진행 상태를 각각 관리합니다. 카탈로그 요청에 실패해도 설치된 스킬을 관리할 수 있습니다. [창](../src/TableCloth.App/Dialogs/SkillMarketplaceWindow.axaml)과 [뷰 모델](../src/TableCloth.App/ViewModels/SkillMarketplaceWindowViewModel.cs)이 이 동작을 구현합니다.

## 버전을 지정하는 별도 XML 카탈로그

카탈로그는 `https://catalog.yourtablecloth.app/SkillCatalog.xml`에서 제공합니다. 원본은 [TableClothCatalog의 docs 디렉터리](https://github.com/yourtablecloth/TableClothCatalog/tree/main/docs)에 두며 `SkillCatalog.xsd`와 기여 안내를 함께 관리합니다. 기존 Pages 워크플로가 `main`에 반영한 파일을 게시합니다.

`SkillCatalog Version="1"` 아래에 고정 ID를 가진 `Skill` 항목을 기록합니다. 각 항목은 GitHub 저장소, 경로, 고정한 원본 커밋을 지정합니다. 설명, 저자, SPDX 식별자, 라이선스 근거, 런타임과 네트워크 요구 사항, 설치 방식, 검토 상태, 적용 조건도 기록합니다. 후보 등록만으로 설치를 허용하지 않습니다. [공용 모델](../src/TableCloth.ManagedAi.Core/SkillCatalog.cs)에 애플리케이션이 읽는 필드를 정의했습니다.

## 원격 설치를 허용하는 검토 조건

원격 설치의 허용 조건을 확인하겠습니다. 목록에 공개한 upstream 스킬 가운데 라이선스 검토를 완료하고 설치를 승인한 항목만 설치할 수 있습니다. 원본 커밋도 고정합니다. 라이선스 근거는 같은 저장소와 커밋의 파일을 가리킵니다. 검토 대기나 거절 상태, 목록 제외 상태, MCP 어댑터 후보에서는 다운로드를 시작하지 않습니다. 설치 시 클라이언트가 스킬 ID로 현재 카탈로그를 다시 조회합니다.

클라이언트는 Git 체크아웃 없이 GitHub REST API로 선택한 파일을 조회합니다. 경로와 저장소 항목을 검사하고 요청 및 다운로드 크기를 제한합니다. 링크와 서브모듈을 거절하며 임시 디렉터리에 파일을 받은 뒤 기존 스킬 가져오기 기능으로 전달합니다. 고정한 라이선스 파일도 `LICENSE.upstream`으로 보존합니다. XML 파서는 외부 엔터티와 DTD를 허용하지 않습니다. [OpenAI 백엔드](../src/TableCloth.ManagedAi.OpenAi/Skills)가 이 검사를 수행합니다.

다만 최초 후보의 검토 상태는 모두 대기로 유지합니다. 후보에 따라 API 키, OAuth 자격 증명, MCP 어댑터 또는 Node.js CLI가 필요합니다. 카탈로그의 적용 조건에 이러한 의존성을 기록합니다. 마켓플레이스는 해당 서비스를 설정하거나 전용 런타임의 실행 권한을 확장하지 않습니다.

## 전용 프로필 안의 로컬 스킬 관리

설치된 스킬 화면에서 폴더 가져오기, 활성화와 비활성화, 확인 후 제거, 새로 고침, 스킬 폴더 열기를 제공합니다. 사용 설정은 이후 AI 작업에 적용합니다. 스킬을 제거하면 해당 전용 폴더도 삭제합니다.

잘못된 `SKILL.md`도 오류 상태로 목록에 표시합니다. 해당 항목을 비활성화하거나 폴더를 열어 확인하고 개별 제거할 수 있습니다. 다른 스킬의 관리도 계속할 수 있습니다. 오류 항목의 활성화는 차단합니다. AI 실행은 잘못된 관리 대상 manifest를 복구하거나 제거할 때까지 오류로 중단합니다.

스킬은 `%LOCALAPPDATA%\TableCloth\ManagedAi\profiles\openai-codex\codex-home\skills`에 보관합니다. 기존 가져오기 기능과 작업 잠금이 변경 작업을 제어합니다. 마켓플레이스는 이 프로필을 관리합니다. 사용자 전역 Codex 프로필과 스킬은 관리 범위에 포함하지 않습니다. [스킬 관리자](../src/TableCloth.ManagedAi.OpenAi/Skills/OpenAiCodexSkillManager.cs)와 [관리 경로](../src/TableCloth.ManagedAi.Core/ManagedAiPaths.cs)에서 저장 범위를 확인할 수 있습니다.

## 자동 검증과 게시 경로의 구분

자동 검증의 범위를 검토하겠습니다. 테스트는 카탈로그 파싱, 검토 조건, 다운로드 검증, 뷰 모델 명령을 다룹니다. Avalonia 헤드리스 테스트는 실제 창을 생성합니다. 테스트에는 합성 스킬과 HTTP 응답을 사용합니다. 후보 서비스의 사용자 자격 증명 연동이나 MCP 어댑터의 동작은 이 테스트로 확인하지 않습니다. [백엔드 테스트](../src/TableCloth.ManagedAi.Test/SkillMarketplaceTests.cs)와 [UI 테스트](../src/TableCloth.Test/SkillMarketplaceTests.cs)에 검증 항목을 기록했습니다.

카탈로그와 애플리케이션은 서로 다른 경로로 배포합니다. TableClothCatalog가 XML을 게시하면 원격 후보를 조회할 수 있습니다. 사용자는 이후 식탁보 빌드에서 마켓플레이스 창을 사용할 수 있습니다. 카탈로그 게시를 기다리는 동안에도 애플리케이션에서 설치된 스킬을 관리할 수 있습니다.

## 후보 검토와 설치 승인

여기까지 정리하면 카탈로그는 후보와 적용 조건을 기록하고 설치 승인 상태를 함께 제공합니다. 관리자는 고정한 원본 리비전의 호환성을 검토한 뒤 upstream 스킬을 승인할 수 있습니다. 애플리케이션의 후보 목록을 코드로 수정하는 절차는 거치지 않습니다.

로컬 스킬 관리는 후보 승인과 독립적으로 사용할 수 있습니다. 서비스 자격 증명, 민감한 문서 접근, MCP 어댑터 개발은 후보별로 검토합니다. 각 후보의 적용 조건과 전용 런타임 호환성을 확인한 결과에 따라 설치를 승인할 수 있습니다.
